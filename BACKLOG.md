- [ ] **Cerebruh's raw↔wiki citation join breaks on typographic apostrophes** (cerebruh, added 2026-08-02) — Found while measuring the Medium corpus for the evaluation above. Some filenames under `wikis/*/raw/` use a curly apostrophe (`’`) while the derived pages in `wikis/*/wiki/` cite the same source with an ASCII apostrophe (`'`), so any exact-string join between a raw source and the pages citing it silently undercounts. Concretely: the Medium scan matched 171 derived pages after normalizing apostrophes and only 159 without — **12 pages whose provenance link is invisible to a naive audit**. 15 raw filenames contain a curly apostrophe in total, so the blast radius is larger than the Medium subset that surfaced it. This is a provenance-integrity defect, not a cosmetic one: it means "which pages depend on this source?" — the question you ask when a source is retracted, superseded, or found wrong — returns an incomplete answer. Fix direction: decide whether to normalize apostrophes at ingest time (changing filenames, which breaks existing citations unless they are rewritten together) or to normalize at comparison time in `AUDITING.md`'s checks (safer, no rewrite, but every future consumer must remember). Then add an assertion to the audit that every `sources:` entry in a wiki page resolves to a file that actually exists under that sub-wiki's `raw/`, which would have caught this and would catch plain typos too. Note `cerebruh/` wiki content is read-only to agents, so any filename change has to run through Cerebruh's own ingest/audit workflow rather than being patched in place.
